/// Format kos tahunan (RM), cth. 23000.0 -> "RM23,000".
/// Kos adalah anggaran latihan, bukan sebut harga rasmi.
String formatCostMyr(double amount) {
  final wholeNumber = amount.toStringAsFixed(0);
  final buffer = StringBuffer();
  for (var i = 0; i < wholeNumber.length; i++) {
    final posFromRight = wholeNumber.length - i;
    buffer.write(wholeNumber[i]);
    if (posFromRight > 1 && posFromRight % 3 == 1) {
      buffer.write(',');
    }
  }
  return 'RM${buffer.toString()}';
}
💡 Gabungan semua topik pagi: function + loop + operator (%, >, &&). Hari 2 kita guna pakej intl (NumberFormat.currency) untuk kerja sama secara automatik.
Latihan penutup pagi: format 23000.0 jadi RM23,000. Snippet penuh boleh dijalankan: hari-1/snippets/dart_asas.dart. Kos diselaras kasar dengan jadual USD rasmi 2021/22 — anggaran latihan.

  • Type-safe — tiada as Programme yang boleh gagal masa jalan

  • Perlu URL / deep-link (cth. versi web)

Jujur dengan peserta: projek kita guna push terus kerana hierarki navigasinya mudah dan linear. Named routes ialah alat yang mereka perlu kenal untuk aplikasi lebih besar.

Status HTTP ≠ ApplicationStatus

Status HTTP

200/201/400/500… — status permintaan rangkaian. POST berjaya (201) = permohonan berjaya dihantar. Itu sahaja.

ApplicationStatus (domain eTT)

Draf → Dihantar → Dalam Semakan → LAYAK / TIDAK LAYAK → Tawaran… — kitaran hayat permohonan, disemak ~7 hari bekerja selepas permohonan ditutup.

💡 201 Created tidak bermakna permohonan sudah "Layak" — kelayakan ditentukan kemudian oleh pihak KPT, bukan oleh kod status HTTP.
Dua paksi status yang selalu dikelirukan pelajar. Enum ApplicationStatus dalam model kita mengekalkan istilah sebenar eTT: eligible dan notEligible, dipaparkan sebagai Layak dan Tidak Layak.

Menghurai Badan Ralat Mengikut Status

Pelayan sering pulangkan mesej ralat sebagai JSON juga — cth. {"error": "icNumber tidak sah"}. Menghurainya mengikut kod status boleh jadi rumit; minta AI rangka fungsinya:


Tulis fungsi Dart yang terima http.Response daripada percubaan
submitApplication(). Jika statusCode 201, pulangkan null (tiada
ralat). Jika 400, cuba jsonDecode response.body dan ambil medan

_load() — Fetch dengan setState()


class _DemoScreenState extends State<DemoScreen> {
  LoadState _state = LoadState.idle;
  List<Programme> _programmes = [];
  final _service = ProgrammeService();

  Future<void> _load() async {
    setState(() => _state = LoadState.loading);
    try {
      final data = await _service.fetchProgrammes();
      setState(() {
        _programmes = data;
        _state = LoadState.loaded;
      });
    } catch (_) {
      setState(() => _state = LoadState.error);
    }
  }

  @override
  void initState() {
    super.initState();
    _load();
  }
Aliran: set loading, await servis, set loaded atau error. try-catch di sini menukar sebarang kegagalan kepada keadaan terkawal — tanpanya, uncaught exception memaparkan skrin merah tanpa laluan cuba lagi.

// ❌ komen "apa" — kod sudah jelas
// tambah 1 pada kaunter
counter++;

// ✅ komen "kenapa" — jelaskan sebab
// Guna fallback tempatan supaya kelas
// boleh diteruskan tanpa internet.
return _fallback();
Komen "apa" cepat lapuk bila kod berubah; komen "kenapa" kekal berguna kerana ia merekod keputusan.

Widget Kecil & Tanggungjawab Tunggal

  • Setiap widget buat satu perkara — build() yang panjang = petanda perlu dipecahkan
  • Row dalam Column dalam Row dalam Padding… melebihi 3–4 lapisan → ekstrak sub-pokok ke widget berasingan
  • Contoh sebenar: CategoryPill, _ChoiceDropdown dalam application_form_screen.dart
  • SRP: satu kelas = satu sebab untuk berubah — ProgrammeService urus data, ProgrammeListScreen urus paparan
Buka projek rujukan dan tunjuk bagaimana widget kecil menjadikan setiap fail mudah dibaca sekali imbas.

  'eTT Mobile',

  • Widget const dibina sekali — Flutter langkau rebuild yang tidak perlu
  • Lint prefer_const_constructors (dalam flutter_lints) mencadangkannya secara automatik — terima cadangannya
const ialah kemenangan prestasi percuma. flutter_lints sudah didayakan lalai dalam projek Flutter baharu melalui analysis_options.yaml.

Refactoring — Ubah Struktur, Kekal Kelakuan

  • Kenal pasti bahagian build() yang berulang atau > 15–20 baris untuk satu "konsep visual"
  • Cipta kelas StatelessWidget baharu; pindahkan kod, tukar rujukan induk kepada parameter constructor
  • Tambah const pada constructor baharu (dan di tempat ia dipanggil)
  • Ganti kod asal dengan pemanggilan widget baharu
  • flutter analyze + uji semula visual — kelakuan mesti kekal sama

Kerja pindah kod berulang begini pun sesuai diserahkan pada AI — "Ekstrak bahagian cip kategori dalam build() ini ke StatelessWidget bernama CategoryPill, kekalkan gaya sama" — kemudian sahkan paparan tidak berubah.

Definisi refactoring: mengubah struktur tanpa mengubah kelakuan. Latihan petang ini: ambil satu widget besar yang dibina pagi tadi dan pecahkan.
