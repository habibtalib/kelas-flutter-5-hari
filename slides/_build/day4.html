JSON → Dart: jsonDecode


import 'dart:convert';

const contohJson =
    '[{"id":"ETT-001","universityName":"Universiti Al-Azhar"}]';

void contoh() {
  final List<dynamic> data = jsonDecode(contohJson) as List<dynamic>;
  print(data[0]['universityName']); // Universiti Al-Azhar
}
  • Objek {} → Map<String, dynamic> · senarai [] → List<dynamic>
  • Masalah: dynamic tidak selamat jenis (type-safe) — menyusahkan dalam UI
jsonDecode memberi struktur generik. Langkah seterusnya: tukar Map dynamic itu kepada objek Dart bertaip penuh melalui factory fromJson.

Programme.fromJson — Model Sebenar


// lib/models/programme.dart
factory Programme.fromJson(Map<String, dynamic> json) {
  return Programme(
    id: json['id'] as String,
    universityName: json['universityName'] as String,
    country: json['country'] as String,
    city: json['city'] as String,
    fieldOfStudy: json['fieldOfStudy'] as String,
    studyLevel: StudyLevel.fromString(json['studyLevel'] as String),
    category: EntryCategory.fromString(json['category'] as String),
    estimatedAnnualCostMyr:
        (json['estimatedAnnualCostMyr'] as num).toDouble(),
    intakeMonth: json['intakeMonth'] as String,
    recognitionNote: json['recognitionNote'] as String,
    quotaSeats: json['quotaSeats'] as int,
  );
}

Kod sebenar dari projek. Tiga butiran penting di slaid seterusnya: enum daripada String, nombor melalui num, dan ketiadaan DateTime.

Butiran Penting fromJson

  • Enum daripada String — StudyLevel.fromString(...) guna firstWhere(..., orElse: ...) supaya app tidak crash jika pelayan hantar nilai luar jangka
  • (… as num).toDouble() — JSON boleh hantar 23000 sebagai int; as num terima kedua-duanya dahulu
  • Tiada medan DateTime — intakeMonth sengaja kekal String biasa ("September")

static EntryCategory fromString(String value) {
  return EntryCategory.values.firstWhere(
    (c) => c.name == value,
    orElse: () => EntryCategory.spm,
  );
}
Corak firstWhere dengan orElse lebih selamat daripada values.byName yang melontar ArgumentError untuk nilai tak dikenali. Tiga butiran ini juga senarai semakan bila menilai model janaan AI petang nanti.

Lapisan Servis — Kenapa Bukan Dalam Widget?

  • Kod http.get tidak diletak terus dalam widget
  • Diasingkan ke lib/services/programme_service.dart
  • Widget cuma panggil satu method: fetchProgrammes()

Kelebihan

Widget tak perlu tahu dari mana data datang. URL boleh ditukar di satu tempat. Servis boleh diuji berasingan dengan http.Client mock.

Corak seni bina yang akan dipuji semasa sesi clean code Hari 5: pengasingan tanggungjawab. Constructor ProgrammeService menerima http.Client pilihan supaya ujian unit boleh suntik client palsu.

ProgrammeService — Kod Sebenar


class ProgrammeService {
  ProgrammeService({http.Client? client})
      : _client = client ?? http.Client();

  final http.Client _client;
  static const String _endpoint =
      'https://raw.githubusercontent.com/kpt-kursus/mock/main/programmes.json';

  Future<List<Programme>> fetchProgrammes() async {
    try {
      final response = await _client
          .get(Uri.parse(_endpoint))
          .timeout(const Duration(seconds: 8));
      if (response.statusCode == 200) {
        final List<dynamic> data =
            jsonDecode(response.body) as List<dynamic>;
        return data
            .map((e) => Programme.fromJson(e as Map<String, dynamic>))
            .toList();
      }
      return _fallback(); // status bukan 200
    } catch (_) {
      return _fallback(); // ralat rangkaian / timeout / JSON rosak
    }
  }
}

Fail sebenar lib/services/programme_service.dart. Perhatikan timeout 8 saat dan dua laluan ke fallback: status bukan 200, dan sebarang exception.

Kenapa Fallback ke Data Tempatan?


/// Simulasi kelewatan supaya penunjuk memuat kelihatan.
Future<List<Programme>> _fallback() async {
  await Future.delayed(const Duration(milliseconds: 600));
  return sampleProgrammes;
}
  • .timeout(8s) — lontar TimeoutException jika pelayan tidak balas
  • try/catch — sebarang kegagalan (tiada internet, DNS, JSON rosak, timeout) dikendalikan sama: jatuh balik
  • Keputusan reka bentuk untuk kelas: WiFi tak stabil atau URL mock belum siap → app tetap berfungsi dengan sampleProgrammes
Dalam app produksi, anda mungkin mahu mesej ralat lebih jelas. Untuk pembelajaran, fallback memastikan tiada seorang pun terhenti kerana isu rangkaian semasa demo.

Menyusun try/timeout/fallback — Mudah Tersilap

Menggabungkan ketiga-tiganya supaya semua jenis kegagalan jatuh balik ke sampleProgrammes mudah tersilap kalau ditulis tergesa-gesa. Kalau buntu, minta AI:


Tulis method fetchProgrammes() dalam kelas ProgrammeService (Dart,
pakej http). Ia perlu: GET ke _endpoint dengan timeout 8 saat, jika
statusCode 200 hurai JSON kepada List<Programme> guna
Programme.fromJson, jika status lain ATAU timeout ATAU sebarang
exception (termasuk JSON rosak) — kembalikan sampleProgrammes
sebagai fallback tanpa throw ralat ke pemanggil.

Semak hasilnya: matikan WiFi dan pastikan ia benar-benar jatuh ke fallback (bukan crash) — sesetengah draf hanya tangkap Exception dan terlepas TimeoutException atau ralat parsing.

Cara sahkan kod rangkaian janaan AI: uji laluan gagal, bukan hanya laluan berjaya. Matikan WiFi ialah ujian paling mudah dan paling mendedahkan.

SESI 7 — JSON → Dart Model, Terus Dari Contoh

Menulis fromJson/toJson secara manual memakan masa & mudah tersilap. Tampal satu rekod contoh kepada AI dan minta kelas penuh:


Berikut satu rekod JSON daripada API tawaran pengajian eTT:
{ "id": "ETT-001", "universityName": "Universiti Al-Azhar",
  "studyLevel": "bachelor", "category": "spm",
  "estimatedAnnualCostMyr": 23000.0, "quotaSeats": 40, … }

Jana kelas Dart `Programme` (immutable, semua medan final) dengan:
- constructor const bernama parameter, semua required
- factory fromJson(Map<String, dynamic> json) + method toJson()
- enum berasingan StudyLevel & EntryCategory, setiap satu dengan
  fromString(String) guna firstWhere(..., orElse: ...) supaya
  tidak crash jika nilai tidak dikenali.
Satu rekod contoh cukup untuk AI kenal struktur — tak perlu tampal keseluruhan fail. Hasilnya patut sangat rapat dengan lib/models/programme.dart sebenar.

Sahkan Model Janaan — Senarai Semak

  • Nullability — dalam Programme semua medan required; tetapi dalam Application, submittedAt mesti DateTime? (draf belum tentu dihantar)
  • Parsing enum — mesti firstWhere(..., orElse: ...), bukan values.byName(...) yang crash untuk nilai tak dikenali
  • Nombor — (json[...] as num).toDouble(), bukan as double terus
  • Jangan tambah medan yang tak wujud — AI kadang "membantu lebih" dengan mereka-reka DateTime.parse untuk medan yang patut kekal String
  • Jalankan flutter analyze, kemudian uji dengan data sebenar: Programme.fromJson(jsonDecode(...)) — pastikan semua medan terisi betul
Kod janaan yang kelihatan betul tidak semestinya betul. Lima semakan ini menangkap hampir semua masalah biasa model janaan AI.

Hantar dengan http.post


Future<bool> submitApplication(Application application) async {
  final response = await http.post(
    Uri.parse('$_baseUrl/applications'),
    headers: {'Content-Type': 'application/json'},
    body: jsonEncode(application.toJson()),
  );
  return response.statusCode == 200 || response.statusCode == 201;
}
  • headers — beritahu pelayan badan berformat JSON
  • jsonEncode(...) — tukar Map kepada String JSON
  • Semak statusCode — jangan andaikan berjaya
Tiga bahagian POST: header content-type, body yang di-encode, dan semakan status. jsonEncode ialah pasangan songsang jsonDecode.

Kod Status HTTP — Apa Aplikasi Patut Buat

KodMaknaTindakan aplikasi
200 OKGET berjayaPapar data (LoadState.loaded)
201 CreatedRekod baharu dicipta (POST)SnackBar kejayaan, tutup borang
400 Bad RequestData dihantar tidak sahPapar ralat borang — jangan biar pengguna sangka berjaya
401 UnauthorizedToken/kebenaran tidak sahHalakan ke log masuk semula
404 Not FoundURL/ID tidak wujud"Rekod tidak dijumpai" — semak _endpoint/ID

Peraturan emas: sentiasa semak statusCode sebelum percaya body. Kod bukan 200/201 mungkin masih ada body — jangan terus jsonDecode dan anggap ia data sah.

Status HTTP ≠ ApplicationStatus

Status HTTP

200/201/400/500… — status permintaan rangkaian. POST berjaya (201) = permohonan berjaya dihantar. Itu sahaja.

ApplicationStatus (domain eTT)

Draf → Dihantar → Dalam Semakan → LAYAK / TIDAK LAYAK → Tawaran… — kitaran hayat permohonan, disemak ~7 hari bekerja selepas permohonan ditutup.

💡 201 Created tidak bermakna permohonan sudah "Layak" — kelayakan ditentukan kemudian oleh pihak KPT, bukan oleh kod status HTTP.
Dua paksi status yang selalu dikelirukan pelajar. Enum ApplicationStatus dalam model kita mengekalkan istilah sebenar eTT: eligible dan notEligible, dipaparkan sebagai Layak dan Tidak Layak.

Menghurai Badan Ralat Mengikut Status

Pelayan sering pulangkan mesej ralat sebagai JSON juga — cth. {"error": "icNumber tidak sah"}. Menghurainya mengikut kod status boleh jadi rumit; minta AI rangka fungsinya:


Tulis fungsi Dart yang terima http.Response daripada percubaan
submitApplication(). Jika statusCode 201, pulangkan null (tiada
ralat). Jika 400, cuba jsonDecode response.body dan ambil medan
"error" sebagai mesej; jika parsing gagal atau medan tiada, pulangkan
"Data tidak sah". Jika 401/404/500, pulangkan mesej generik yang
sesuai. Fungsi ini TIDAK boleh throw — sentiasa pulangkan
String? mesej ralat atau null.

Semak: adakah ia jsonDecode badan yang mungkin bukan JSON sah (cth. HTML halaman ralat 500)? Bungkus bahagian itu dalam try/catch tersendiri.

Draf AI yang tidak berhati-hati boleh terlontar ralat parsing baharu semasa cuba mengendalikan ralat asal — ironinya kod pengendali ralat sendiri crash. Ujilah dengan body bukan-JSON.

Empat Keadaan Operasi Rangkaian: LoadState


enum LoadState { idle, loading, loaded, error }
KeadaanBilaUI dipaparkan
idleSebelum fetch pertamaSama seperti loading
loadingfetchProgrammes() sedang berjalanCircularProgressIndicator
loadedData diterima (API atau fallback)Senarai ProgrammeCard
errorKegagalan tanpa fallbackIkon + mesej + butang Cuba Lagi
💡 Satu enum lebih jelas daripada beberapa boolean berasingan seperti isLoading & hasError.
Corak yang sama digunakan oleh ProgrammeProvider dalam projek sebenar. Satu sumber kebenaran untuk keadaan skrin — mustahil loading dan error benar serentak.

_load() — Fetch dengan setState()


class _DemoScreenState extends State<DemoScreen> {
  LoadState _state = LoadState.idle;
  List<Programme> _programmes = [];
  final _service = ProgrammeService();

  Future<void> _load() async {
    setState(() => _state = LoadState.loading);
    try {
      final data = await _service.fetchProgrammes();
      setState(() {
        _programmes = data;
        _state = LoadState.loaded;
      });
    } catch (_) {
      setState(() => _state = LoadState.error);
    }
  }

  @override
  void initState() {
    super.initState();
    _load();
  }
Aliran: set loading, await servis, set loaded atau error. try-catch di sini menukar sebarang kegagalan kepada keadaan terkawal — tanpanya, uncaught exception memaparkan skrin merah tanpa laluan cuba lagi.

build() — switch Atas Keadaan


switch (_state) {
  case LoadState.idle:
  case LoadState.loading:
    return const Center(child: CircularProgressIndicator());
  case LoadState.error:
    return Center(
      child: Column(mainAxisSize: MainAxisSize.min, children: [
        const Icon(Icons.wifi_off, size: 48, color: Colors.grey),
        const Text('Gagal memuat data program.'),
        FilledButton(onPressed: _load, child: const Text('Cuba Lagi')),
      ]),
    );
  case LoadState.loaded:
    return ListView.builder(
      itemCount: _programmes.length,
      itemBuilder: (context, i) =>
          ProgrammeCard(programme: _programmes[i]),
    );
}
✅ switch tanpa default atas enum lengkap = exhaustive switch — Dart beri amaran masa kompil jika satu keadaan terlepas.
CircularProgressIndicator wajib semasa loading — tanpanya skrin kosong buat pengguna keliru sama ada app hang atau sedang memuat. Butang Cuba Lagi cuma panggil semula _load.

Blok ikon + mesej + butang Cuba Lagi agak berulang untuk ditulis tangan setiap kali ada skrin baharu yang fetch data. Minta AI bina rangkanya:


Bina widget Flutter reusable ErrorStateView yang terima String

Pilih ikut situasi: GitHub raw paling mudah untuk kelas, json-server untuk demo ubah data secara langsung, mocki.io bila perlu URL awam tanpa repo.

Dua Perangkap Selepas Tukar _endpoint

  • Emulator Android localhost tidak menunjuk ke komputer anda — guna http://10.0.2.2:3001/programmes (alias khas emulator). Peranti fizikal: IP rangkaian komputer, WiFi sama.
  • Hot restart _endpoint ialah static const — tekan R besar (hot restart), bukan r kecil (hot reload), supaya main() dijalankan semula.
💡 Selepas restart, tarik-untuk-muat-semula dan sahkan data datang dari pelayan sebenar, bukan fallback tempatan.
Dua isu yang pasti timbul di kelas. 10.0.2.2 kerana emulator berjalan dalam mesin maya tersendiri; hot restart kerana pemalar const tidak dimuat semula oleh hot reload.

build() — switch (_state)
  ├─ loading/idle → CircularProgressIndicator
